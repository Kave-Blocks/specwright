Spec: [`context/feature-specs/10-liveblocks-setup.md`](../feature-specs/10-liveblocks-setup.md)

- `10-liveblocks-setup.md` — complete. Realtime collaboration infrastructure is wired at the server/config layer (no client hooks or canvas yet). `liveblocks.config.ts` now types **Presence** (`cursor: {x,y} | null`, `isThinking: boolean`) and **UserMeta** (`id` + `info: { name, avatar, color }`); the unused `Storage`/`RoomEvent`/`ThreadMetadata`/`RoomInfo` slots were changed from the scaffold's `{}` to `Record<string, never>` to satisfy `@typescript-eslint/no-empty-object-type`. `lib/liveblocks.ts` holds a **cached** Liveblocks node client (`getLiveblocks()`, global-cached like `lib/prisma.ts`, lazy so importing never throws when `LIVEBLOCKS_SECRET_KEY` is unset at build time) plus `getUserColor(userId)` — a deterministic string-hash → fixed 10-color palette mapping so a user's cursor keeps the same color everywhere. `app/api/liveblocks-auth/route.ts` (`POST`) mints session tokens: (1) requires a Clerk user (`currentUser()` → `401`), (2) reads the room from the body and treats the **room id as the project id**, verifying access via the existing `getAccessibleProject` helper (missing + no-access both collapse to `403`), (3) ensures the room exists (`getRoom` → on miss `createRoom` with `defaultAccesses: []`, create-race swallowed), (4) `prepareSession` with `userInfo` = display name (full name → username → email → "Anonymous"), avatar (`imageUrl` when `hasImage`, else `""`), and the generated cursor color, grants `FULL_ACCESS` to the room, and returns the authorize body/status. **Dependency note:** the spec said "all required Liveblocks packages are already installed," but only `@liveblocks/{client,react,react-flow,react-ui}` were present — `@liveblocks/node` (needed for the server client + session tokens) was missing and was installed (`^3.22.0`). A `LIVEBLOCKS_SECRET_KEY=` placeholder was appended to `.env.local` (empty — no real key yet; the route throws a clear error at runtime until one is set). Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean; `/api/liveblocks-auth` registered as a dynamic route). Note: the auth route was not exercised live end-to-end because no real Liveblocks secret key is provisioned yet.
