# 11 — base-canvas

Spec: [`context/feature-specs/11-base-canvas.md`](../feature-specs/11-base-canvas.md)

- `11-base-canvas.md` — complete. Replaced the `/editor/[roomId]` canvas placeholder with a Liveblocks-backed React Flow canvas. The workspace **page stays a Server Component**; all canvas/Liveblocks work lives in new client components under `components/editor/canvas/`. **Room wrapper** `canvas-room.tsx` (`CanvasRoom({ roomId })`) sets up the room: `LiveblocksProvider authEndpoint="/api/liveblocks-auth"` → `RoomProvider id={roomId} initialPresence={{ cursor: null, isThinking: false }}` (both Presence keys are required by the typed `Presence` from `liveblocks.config.ts`, so `isThinking: false` is set alongside the spec's `cursor: null`) → `CanvasErrorBoundary` (error fallback) → `ClientSideSuspense` (loading fallback) → `Canvas`. Suspense hooks/components are imported from **`@liveblocks/react/suspense`**. `roomId` is the project id (`projectId` prop), keeping room id ≡ project id as the auth route expects. **Loading/error states** are small local components: `CanvasLoading` (spinning `Loader2` + "Loading canvas…") and `CanvasError` ("Couldn't connect to the canvas") — both `flex h-full w-full` centered so they fill the sized `<main>`. **Error boundary** `canvas-error-boundary.tsx` is a minimal `Component` class (getDerivedStateFromError + componentDidCatch → `console.error`); `react-error-boundary` was **not** installed to avoid a new dependency for a one-off fallback. **Canvas** `canvas.tsx` calls `useLiveblocksFlow<CanvasNode, CanvasEdge>({ suspense: true, nodes: { initial: [] }, edges: { initial: [] } })` and passes the synced `nodes`/`edges` + `onNodesChange`/`onEdgesChange`/`onConnect`/`onDelete` into `<ReactFlow<CanvasNode, CanvasEdge>>` with `connectionMode={ConnectionMode.Loose}` (loose connections), `fitView`, and children `<Background variant={BackgroundVariant.Dots} />` (dot pattern) + `<MiniMap />`. CSS is imported in `canvas.tsx` (`@xyflow/react/dist/style.css` + `@liveblocks/react-flow/styles.css`) — Next 16 App Router permits external-package stylesheet imports in colocated client components. **Shared types** live in `types/canvas.ts`: `CanvasNodeShape` (`"rectangle" | "ellipse" | "diamond"`), `CanvasNodeData` (`label`/`color`/`shape`), the `CANVAS_NODE_TYPE = "canvasNode"` / `CANVAS_EDGE_TYPE = "canvasEdge"` constants, and `CanvasNode = Node<CanvasNodeData, "canvasNode">` / `CanvasEdge = Edge<Record<string, unknown>, "canvasEdge">`. **Wiring:** `editor-workspace.tsx`'s central `<main>` changed from a centered placeholder to `relative flex-1 overflow-hidden rounded-2xl border border-surface-border bg-base` holding `<CanvasRoom roomId={projectId} />` — `relative` + the flex chain give React Flow a definite-height parent to fill. **Per scope:** no controls, no custom node/edge rendering (only the type names are defined), no persistence, no AI, no `<Cursors />` (not in the spec's render list). Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean; `/editor/[roomId]` still a dynamic route). **Not exercised live in-browser** because no real `LIVEBLOCKS_SECRET_KEY` is provisioned yet (same constraint noted in `10`) — the room can't authenticate until a key is set, so runtime multiplayer sync is unverified.
