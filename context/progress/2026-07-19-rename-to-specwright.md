# Project renamed: Ghost AI → Specwright

_2026-07-19 — not spec-driven._

- **Project renamed: Ghost AI → Specwright.** Brand-only; no behavior changed. 16 files touched across source, user-facing copy, and context docs, plus `package.json`/`package-lock.json` (`ghost-ai` → `specwright`). **Three things were deliberately left alone, and the distinction is the whole risk of this change.** (1) **`variant="ghost"`** — the shadcn button style — and the **`ghost` drag-preview** in `tool-panel.tsx`/`13-node-shape.md` share the word but not the referent; a naive find-and-replace breaks the UI. Only the exact string `"Ghost AI"` was replaced, which is unambiguous (verified: zero `GhostAI`/`ghostai` variants existed), and the per-file bare-`ghost` counts were compared before and after to prove nothing was lost. (2) **`AI_USER_ID = "ghost-ai"`** (`trigger/design-agent.ts:17`) and the matching **`id: "ghost-ai"`** (`types/tasks.ts:89`) are kept — this is the AI's author ID on Liveblocks feeds, and messages already persisted in existing rooms carry it, so renaming the key would orphan their attribution. Only the **display name** (`AI_NAME`, `AI_CHAT_ASSISTANT_SENDER.name`) changed, which is the half users actually see. (3) **`.playwright-mcp/` capture logs** are historical QA records, not source; rewriting them would falsify the record. **One change grep could not have found:** the brand lockup in `auth-layout.tsx` used lucide's literal **`Ghost` icon**, swapped to **`DraftingCompass`** — the only non-textual artifact of the old name. `03-auth.md` describes it as "cyan logo mark" and so stayed accurate. **No external service needed touching** — Clerk, Liveblocks, Trigger.dev, and Blob are all referenced by opaque key/ID (`proj_*`, `sk_*`), with no name strings hardcoded; their *dashboard* project names are still "Ghost AI" and are the remaining manual step. **Verified:** `tsc --noEmit`, `npm run lint`, and `npm run build` all clean (all 18 routes registered). The GitHub repo was renamed `ghost-ai-ban` → `specwright` via `gh repo rename` (history/issues preserved, local remote repointed, both the new URL's reachability and the old URL's redirect confirmed by `git ls-remote`). Shipped as **two commits** rather than one: `4106965` (the `33` interview work, which was sitting uncommitted when the rename began) and `49afbda` (the rename alone). A file-level split was impossible — `ai-sidebar.tsx`, `ai-architect-tab.tsx`, `architecture-interview.tsx`, and this file each carry **both** changes — so it was split by reversing the substitution, committing `33` in isolation, then re-applying the rename from a snapshot, verifying at each step that the `33` diff contained zero `Specwright` and the rename diff touched nothing but brand strings and the logo icon. The local folder is now **`~/work/specwright`**; `.next` was cleared and rebuilt afterwards, because `required-server-files.json` had baked in the old absolute path.

- **Open risk on the name itself — checked *after* the rename, which was the wrong order.** `specwright` is **taken on npm** (v3.6.3, published 2025-12-29, last updated 2026-02-26) by **AmElmo/SpecWright**: *"AI agents orchestrator that writes your PRDs, design briefs, and tech specs before you code. Works with Claude Code, Codex, Cursor, and more."* That is **the same product category as this one** — not a string collision but a competitor collision, which is the kind that matters (likelihood of confusion turns on category, not spelling). It is small (7 stars, 62 downloads/month, homepage `specwright.argil.io`) but actively maintained. `specwright.com`/`.io` were registered 2018-12-06 to a single GoDaddy holder and are parked; `specwright.ai` was registered 2026-01-26 via NameCheap, ~4 weeks after their npm launch, so presumably theirs. **The name was kept as a deliberate deferral, not a clearance** — this is a 2-person internal tool, so the registry questions are premature, but the competitor collision must be resolved before anything ships publicly. `charrette` was verified **free on npm** with no product collision. Note also that the *previous* name's clash (ghost.org) was in publishing/CMS — a **different** category, and therefore a weaker risk than the current one.

- **Brand mark designed and wired in — the rename's last non-textual loose end.** The rename entry below notes that `auth-layout.tsx` used lucide's literal `Ghost` icon and was swapped to **`DraftingCompass`**; that was a placeholder, and the app had **no logo at all** (`public/` was empty). There is now a real mark: an **"S" traced as a smooth-step canvas edge**, terminating in two connection-node rings. The concept is deliberately *not* a metaphor invented for the brand — it is drawn in **the app's own visual grammar** (the orthogonal smooth-step routing of `CanvasEdgeRenderer`, plus rings that read as the connection handles), on **Lucide's 24px grid at stroke-width 2**, so it sits beside the icon set as a peer. **Four concepts were drawn and rendered before choosing, which is what settled it** — a graph fanning into spec lines, a spec page containing a graph, and a three-shape node cluster all collapsed into unreadable blobs at 32px and below, while the S held down to **16px**. Judged from actual screenshots at 16/24/48/96/120px on `--bg-base` and on a light surface, not from reasoning about the paths. **One structural decision is load-bearing and easy to undo by accident:** the first pass punched the node rings out with a `#080809` fill, which would have rendered a dark blob on **any** surface but the page background. The shipped path instead **stops at each ring's edge** so the stroke flows into it — no fill, so the mark inherits **`currentColor`** and is safe anywhere. `ui-context.md` records this as a rule because "clean up the rings with a background fill" is the obvious wrong fix. **Wired in three places** via a new **`components/ui/logo.tsx`** (`LogoMark` = mark only; `Logo` = mark + wordmark, sized from a single text utility because the wordmark inherits its root's font-size): the `DraftingCompass` **placeholder tile in `auth-layout.tsx`** is gone, replaced by the lockup unwrapped (a stroke mark inside a filled brand tile fights the cyan-on-dark treatment its own feature icons use); the **`editor-navbar.tsx` center slot**, which was a literally empty `<div>`, now holds the lockup; and **`workspace-navbar.tsx`** gains the bare mark at the left of the sidebar toggle — that navbar had no branding at all, and its center is spoken for by the project name. Favicon is **`app/icon.svg`** via Next's file convention (confirmed against `node_modules/next/dist/docs/.../app-icons.md` rather than assumed — `.svg` is valid for `icon` but **not** for `favicon`, which is `.ico`-only), so **no `metadata.icons` entry is needed**; the build registers `/icon.svg` as a static route. **Verified:** `tsc --noEmit`, `npm run lint`, and `npm run build` all clean (all 18 routes, plus `/icon.svg`). The **auth layout was screenshotted in the running app**, real CSS and real Geist. The **two navbars are behind the Clerk wall and were driven through a temporary preview route**, since deleted — confirmed gone by `git status` and by its absence from the build's route table. **Not done:** the mark is not a link anywhere (no navigate-home affordance was added, since that is a behavior change rather than branding); no `apple-icon`, no OG image, no `.ico` fallback for legacy browsers that ignore SVG favicons.

- **Two findings surfaced while verifying the above, neither of them logo work.** (1) **The Clerk sign-in card renders "Sign in to Ghost AI" to end users** — screenshotted in the live app. The rename entry below correctly predicted that external dashboards still carry the old name and listed it as "the remaining manual step"; this confirms it is **user-visible on the first screen of the product**, not merely an internal label. It is a Clerk *dashboard* application-name setting, so no code change can fix it. (2) **The public-route matcher in `proxy.ts` matches by prefix, not by path.** `createRouteMatcher([`${SIGN_IN_URL}(.*)`])` with `SIGN_IN_URL=/sign-in` makes **every path beginning `/sign-in` public** — `/sign-inventory`, `/sign-in-admin`, and so on — not just `/sign-in` and its children. This was used deliberately (a temp route named `sign-in-preview` was reachable without touching auth config, which is *how* the navbars got verified) and that is precisely why it is worth recording: it means an unrelated future route can be made public by its name alone. The fix, when it matters, is anchoring — `/sign-in(/.*)?$` — rather than a bare `(.*)` suffix.
