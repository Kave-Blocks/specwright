# 21 — canvas-autosave

Spec: [`context/feature-specs/21-canvas-autosave.md`](../feature-specs/21-canvas-autosave.md)

- `21-canvas-autosave.md` — complete. Persist the collaborative canvas so project state survives a reload (groundwork before AI generation): canvas JSON lives in **Vercel Blob**, and the blob URL lives on the Prisma project record. **Schema (item 1)** — no migration needed: the `Project.canvasJsonPath String?` field already existed (and is in the `0_init` migration), so it was **reused** as the blob-URL reference, keeping Prisma metadata-only per `architecture-context.md` (which already documented `canvas/{projectId}.json` + `canvasJsonPath`, so this feature matches the pre-declared storage model — no doc drift, no context-file edits). **Dependency** — `@vercel/blob@^2.6.1` installed (was missing); `BLOB_READ_WRITE_TOKEN` was **already present** in `.env.local` (unlike the Liveblocks-key situation in `10`). **Storage helpers** `lib/canvas-storage.ts` — `canvasBlobPath(projectId)` → the deterministic `canvas/{projectId}.json` path (so every save overwrites the same object and the stored URL stays stable), and `parseCanvasSnapshot(unknown)` → validates the top-level `{ nodes, edges }` array contract at the boundary (both the PUT body **and** the JSON fetched back from Blob pass through it; malformed/partial → `null`). Node/edge internals are left to React Flow/Liveblocks — matching the project's existing shallow `readJsonBody` boundary style. **API route (item 2)** `app/api/projects/[projectId]/canvas/route.ts` — both handlers wrapped in **`withProjectMember`** (owner **or** collaborator), not `withProjectOwner`, because the canvas is collaboratively edited so a collaborator's autosave must succeed. The provisioned Blob store is a **private** store, so blobs are written and read with **private access** (a first attempt with `access: "public"` returned `500 Vercel Blob: Cannot use public access on a private store` — a private blob URL is also not publicly fetchable, so the read path uses the SDK, not `fetch`). **`PUT`**: `parseCanvasSnapshot(await readJsonBody(...))` → `400` on a bad payload; `put(canvasBlobPath, JSON.stringify(snapshot), { access: "private", contentType: "application/json", addRandomSuffix: false, allowOverwrite: true })` — `addRandomSuffix:false`+`allowOverwrite:true` keep the blob **URL constant** across saves (so `canvasJsonPath` never churns and old blobs aren't orphaned); then `prisma.project.update` writes `blob.url` to `canvasJsonPath`. **`GET`**: reads `canvasJsonPath` from Prisma (`findUnique`, `select: { canvasJsonPath: true }` — `withProjectMember`'s `AccessibleProject` doesn't carry it), returns `{ canvas: null }` when unset, otherwise reads the blob back through the SDK's authenticated `get(canvasBlobPath, { access: "private", useCache: false })` (`useCache:false` guarantees the freshest content; `null`/non-`200` → `{ canvas: null }`) and parses the stream via `new Response(result.stream).json()` → `parseCanvasSnapshot` → `{ canvas }`. New route registered as a dynamic function route. **Autosave hook (item 3)** `hooks/use-canvas-autosave.ts` (`useCanvasAutosave({ projectId, nodes, edges, enabled })` → `{ status, saveNow }`) — watches `nodes`/`edges` and, once `enabled`, **debounces 1500ms** (`AUTOSAVE_DELAY_MS`) before `PUT`ing the latest graph; tracks `CanvasSaveStatus` = `idle | saving | saved | error` (added to `types/canvas.ts` alongside `CanvasSnapshot`). A `skipNextChange` ref skips the first change after enabling (the loaded/empty baseline, not a user edit); the live graph is read through a `latestGraph` ref (synced in an effect, **not during render** — see lint note) so `save` never has to be recreated on each keystroke (which would reset the debounce), and `saveNow` (manual/retry) still sends the freshest state; an `AbortController` cancels any save superseded by a newer one (last-write-wins, and an intentional abort is not reported as `error`). The debounce effect sets `saving` immediately on edit for instant feedback, then persists once edits settle. **Load-on-empty (item 4)** — a run-once mount effect in `CanvasFlow` (`canvas.tsx`): if the room already has nodes/edges it **skips the load entirely** (never clobbers active collaboration) and just marks hydrated; otherwise it `GET`s the saved snapshot, **re-checks the room is still empty** (defensive against a collaborator adding nodes while the fetch was in flight — via a `loadRef` synced each render), and only then adds the saved nodes/edges through the same synced `onNodesChange`/`onEdgesChange` `"add"` flow used by template import, then `fitView` inside a double-`requestAnimationFrame` (so RF's store reflects the new nodes first). It always sets `hydrated` in `finally`, which **gates the autosave** (`enabled={hydrated}`) so loading/empty state never triggers a save on its own. **Save indicator (item 5)** `components/editor/save-status-button.tsx` (`SaveStatusButton`) — a ghost `size="sm"` navbar button mapping each status to icon+label+token color: `Save`/`Cloud` (`text-copy-muted`), `Saving…`/spinning `Loader2` (`text-copy-muted`, disabled), `Saved`/`Check` (`text-success`), `Error`/`AlertCircle` (`text-error`); clicking flushes an **immediate save** (manual save / error retry) via `saveNow`, with `title`/`aria-label` hints and a `min-w-19` to avoid width jitter. Added to `workspace-navbar.tsx`'s right cluster (before Templates) via new `saveStatus`/`onSave` props. **Cross-room-boundary bridge** `components/editor/canvas/canvas-save-context.ts` (`CanvasSaveProvider`/`useCanvasSave`, mirroring the `starter-templates-context` pattern) — the status indicator lives in the navbar (**outside** the Liveblocks room) while the autosave hook runs in `CanvasFlow` (**inside** the room, where the synced node/edge state exists). `EditorWorkspace` owns `saveStatus` state + a `saveNowRef`, provides a **memoized-stable** `{ setStatus, saveNowRef }` (so status changes don't re-render the room subtree via a new context value), wraps its subtree in the provider, and passes `saveStatus` + `onSave={() => saveNowRef.current?.()}` down to the navbar; `CanvasFlow` mirrors the hook's status up through `setStatus` and registers `saveNow` on `saveNowRef`. `projectId` is threaded `CanvasRoom` → `Canvas` → `CanvasFlow` (room id ≡ project id). **Lint note:** the `react-hooks/refs` rule forbids mutating a ref during render, so both "latest value" refs (`latestGraph`, `loadRef`) are synced inside effects — safe because every consumer (`save` via `setTimeout`/click, the post-fetch re-check) runs asynchronously, after commit. **Scope honored:** no AI generation, no versioning, no manual-only save mode; the canvas/edge/node rendering, presence/cursors, controls, and template import were left untouched (the only `canvas.tsx` additions were the load effect + autosave wiring). Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean), plus a 9-case unit check of the storage helpers (path determinism + JSON round-trip + every malformed-payload rejection) and a live route smoke test (`GET`+`PUT /api/projects/test-proj/canvas` unauthenticated → clean `401 {"error":"Unauthorized"}`, proving the route runs and the `withProjectMember` guard fires before any DB/Blob work), and a **real Blob round-trip against the provisioned private store** (`put`→`get`→`del` with the actual `BLOB_READ_WRITE_TOKEN`, exercising the exact private-access calls the route makes: private `put` returned a `…private.blob.vercel-storage.com` URL and `get` read the identical payload back at `statusCode 200`). **Live-QA confirmed end-to-end**: after the private-access fix, a real project (`hello-pr5xvs`) autosaved a 9-node/7-edge CI/CD graph to `canvas/hello-pr5xvs.json` (4.35 kB in the store) with the blob URL persisted on the Prisma record. **Review-pass refinements** (post-QA, scoped to a follow-up review): GET now reads via the **stored URL** (`project.canvasJsonPath`) rather than the derived pathname — same object, matching the spec wording (verified `get(url)` → `statusCode 200`); and the Save button gained **auto-revert** — `saved`/`error` show briefly (`STATUS_RESET_MS` = 2000 ms) then return to idle ("Save") via a `status`-watching effect in `useCanvasAutosave` (a fresh `saving` cancels the pending reset; `status` isn't a dep of the debounce effect, so the reset never triggers a spurious save). The Save button lives only in `WorkspaceNavbar`, never in the separate `EditorNavbar` (editor home), so the "not on editor home" requirement holds structurally — no conditional needed. **Not exercised in the full editor live** for the same reason as `10`–`20`: the editor is behind the Clerk auth wall and this session has no sign-in credentials, so the end-to-end autosave→Blob→Prisma round-trip and the load-on-empty path are verified structurally (types/build/lint + unit + route smoke test) and traced against the `@vercel/blob` `put` API + the existing Liveblocks change-flow, not via a signed-in browser session.
