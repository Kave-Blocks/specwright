# Multiplayer presence: remote selection + cursor tuning

_2026-07-13 — not spec-driven._

- **Multiplayer presence: remote selection added, live cursors audited + tuned** (reported as "I can't tell whether other users' cursors show, and I can't see what another user has selected"). **Live cursors were already implemented and correct** — presence is written on mouse move in `canvas.tsx` (`screenToFlowPosition` → `updateMyPresence({cursor})`, cleared to `null` on `onMouseLeave`) and read in `live-cursors.tsx`, which is mounted as a child of `<ReactFlow>` inside the `RoomProvider`. Cursors are stored in **flow coordinates** and re-projected per viewer with that viewer's own `[translateX, translateY, zoom]`, so they stay anchored to canvas content under independent pan/zoom. No fix was needed; the reporter simply had no way to test it with one mouse. **Remote selection did not exist and was built.** It cannot ride on the synced graph: `@liveblocks/react-flow` hard-codes `selected: false` in its `NODE_BASE_CONFIG`/`EDGE_BASE_CONFIG`, deliberately keeping selection out of Storage so one user's selection can never clobber another's. Selection therefore travels through **presence**, alongside the cursor: `Presence` gained `selection: { nodes: string[]; edges: string[] } | null` (`liveblocks.config.ts`, `initialPresence` in `editor-room.tsx`, and `selection: null` in the AI agent's `setPresence` so every participant's presence keeps one shape). `canvas.tsx` broadcasts via React Flow's `onSelectionChange`. New `components/editor/canvas/remote-selection-context.tsx` holds **one** presence subscription for the whole flow and exposes `useRemoteNodeSelectors(id)` / `useRemoteEdgeSelectors(id)` through context, so N nodes don't open N subscriptions; `canvas-node.tsx` draws a bounding box + name tag in the selector's presence color (a box, not a shape trace, so it reads the same on diamonds/circles and matches the resizer's box) and `canvas-edge.tsx` takes over the edge stroke color, thickens it, and renders a matching name badge through `EdgeLabelRenderer` at the path midpoint, lifted clear of the edge's own label pill (a remote selection forces that pill to show, so the two would otherwise overlap). Both node and edge badges show `+N` when more than one participant holds the same element. **Presence performance** — three components called a bare, unselected `useOthers()` (`live-cursors.tsx`, `presence-avatars.tsx`, `hooks/use-ai-status.ts`), so every remote *cursor move* (up to 10/sec/person) re-rendered all of them; the repo's own `.agents/skills/liveblocks-best-practices` warns about exactly this. Now: `live-cursors.tsx` uses `useOthersConnectionIds()` + a per-cursor `useOther(id, selector, shallow)`; `presence-avatars.tsx` uses `useOthersMapped` over identity fields only; `use-ai-status.ts` selects straight down to a boolean. `remote-selection-context.tsx` likewise uses `useOthersMapped` with an explicit selection-equality check, so cursor movement never re-renders nodes/edges. **Cursor smoothing vs. pan/zoom** — `cursor.tsx`'s 100ms `transition-transform` smoothed throttled network updates but *also* animated the reposition caused by the local viewport transform, so remote cursors visibly lagged the canvas while panning. Restructured into two layers: `live-cursors.tsx` applies the viewport transform to a wrapper **with no transition** (cursors stay locked to content during pan/zoom), and each `Cursor` translates to its **flow** coordinates inside it with the transition, counter-scaling by `1/zoom` so the pointer and badge keep a constant on-screen size as in Figma. **Testing:** added `scripts/simulate-cursor.ts` (`pnpm simulate:cursor <roomId> [elementId...]`), which injects a phantom participant — moving cursor + held selection — via the node SDK's `setPresence`, the same path the AI agent uses. It reads the room's real node/edge ids out of Storage (`{ flow: { nodes, edges } }`, keyed by id), auto-selects the first node when none is named, and clears presence on Ctrl-C. This makes both features verifiable in a single browser window with one mouse. Verified with `tsc --noEmit` and `eslint` (both clean) and by running the simulator against a live room (presence writes accepted; real ids resolved). Note: the two-browser human-to-human path was not re-exercised in a live signed-in session — the phantom exercises the identical presence path.
