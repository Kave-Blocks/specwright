# 20 — ai-sidebar-shell

Spec: [`context/feature-specs/20-ai-sidebar-shell.md`](../feature-specs/20-ai-sidebar-shell.md)

- `20-ai-sidebar-shell.md` — complete. Turned the right-hand AI sidebar from a "coming soon" placeholder into a proper tabbed chat shell. **Open/close stays parent-controlled** (`EditorWorkspace` owns `isAiSidebarOpen`) and the existing floating/slide-in treatment is **untouched** — same `bg-surface/95` surface, `border-surface-border`, `shadow-2xl`, `backdrop-blur`, and the docked-column-at-md / slide-over-overlay-on-mobile positioning classes were preserved verbatim (only `overflow-hidden` was added to the card so the new scroll regions clip to the rounded corners). **New files:** `components/editor/ai/ai-architect-tab.tsx` and `components/editor/ai/specs-tab.tsx`; `components/editor/ai-sidebar.tsx` was rewritten from placeholder body → header + shadcn `Tabs`. **Header** (`ai-sidebar.tsx`): a `Bot` icon in a `size-9 rounded-lg bg-subtle text-ai-text` badge (the AI-accent identity, matching the navbar's `Sparkles` toggle), title **"AI Workspace"** (`text-copy-primary`) + subtitle **"Collaborate with Specwright"** (`text-copy-muted`), and the close button (`Button variant="ghost" size="icon-sm"`) right-aligned. **Tabs** (`shadcn`/Base UI): **"AI Architect"** / **"Specs"** in a full-width `TabsList`; active trigger overridden to `bg-accent-dim` + `text-brand`, inactive left `text-copy-muted`. Because Base UI's `TabsTrigger` ships `dark:data-active:bg-input/30`/`dark:data-active:text-foreground` (and the app is always in `dark` mode), the override includes the **`dark:data-active:` variants too** (`dark:data-active:bg-accent-dim dark:data-active:text-brand`) so tailwind-merge deduping actually wins in dark mode — a plain `data-active:` override alone would be beaten by the base `dark:` rules. **Token mapping (per spec item 6 — "use existing project tokens; check globals.css/ui-context"):** the spec names colors loosely; they resolve to real tokens — `text-primary-text`→`text-copy-primary`, `text-muted-text`→`text-copy-muted`, `bg-accent`(tab)→`bg-accent-dim`, `text-accent`/`text-accent-text`→`text-brand`, `bg-brand-dim`→`bg-accent-dim`, `bg-accent`(buttons)→`bg-brand`. The sidebar surface kept the **existing `bg-surface/95`** rather than the spec's illustrative `bg-base/95` because (a) item 1 says preserve the existing background and (b) `bg-base` is a standalone `@utility` with **no `/95` opacity support** (only `--color-*` tokens like `surface` support the slash-opacity modifier). Two accent colors are used deliberately: **brand cyan** for interactive accents (tabs / chips / buttons / user-bubble tint) and **AI indigo** (`text-ai-text`) for the two decorative `Bot` marks (header badge + empty state). **AI Architect tab** — a `flex h-full flex-col` with a `ScrollArea flex-1` chat region over a bordered input dock. Empty state (shown when `messages.length === 0`): a `size-12` `Bot` badge (`bg-subtle text-ai-text`), a short description, and three **starter chips** (`Design an e-commerce backend` / `Create a chat app architecture` / `Build a CI/CD pipeline`) styled as soft pills (`rounded-full bg-subtle text-brand`, hover `bg-elevated`) — clicking a chip sends it. Local `useState<ChatMessage[]>` drives the list; **`send()` appends the user message plus a single static canned assistant reply** (`ASSISTANT_PLACEHOLDER` — no AI/backend, just so the assistant bubble style isn't dead code; ids from a `useRef` counter). **User bubbles** right-aligned `border-2 border-brand/50 bg-accent-dim text-copy-primary`; **assistant bubbles** left-aligned `border border-surface-border bg-elevated text-brand`; both `max-w-[85%] rounded-2xl wrap-break-word whitespace-pre-wrap`. Input is the shadcn `Textarea` (`min-h-18`=72px, `max-h-40`=160px, `resize-none`; auto-grow via the base class's `field-sizing-content`) with an absolutely-positioned `size-icon-sm` send `Button` (`bg-brand text-white`, disabled when the trimmed input is empty). **Enter submits, Shift+Enter newlines** (keydown guard), and a `useEffect` scrolls a bottom sentinel into view on new messages; a `text-copy-faint` hint line documents the shortcut. **Specs tab** — a full-width **"Generate Spec"** `Button` (`bg-brand text-white`, `Sparkles` icon, currently inert — no generation logic) above a `ScrollArea` holding one **static demo spec card** (`rounded-xl border border-surface-border bg-elevated`): a `FileText` icon badge, title, a `line-clamp-2` snippet, and a **disabled** `Download` action (`Button variant="outline"`). **Scope honored:** no backend, no Liveblocks/presence, no AI generation, and the sidebar's open/close mechanics were not rebuilt — this is purely the sidebar UI structure. Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean; the two lint canonical-class nudges — `min-h-[72px]`→`min-h-18`, `break-words`→`wrap-break-word` — were applied). **Not exercised live in-browser** for the same reason as `10`–`19`: the editor is behind the Clerk auth wall and this session has no sign-in credentials. The AI sidebar is self-contained (no Liveblocks/Clerk deps), but a preview route would also be gated by `proxy.ts`, so the tab switching, chat send/auto-resize, and active-tab override are verified structurally (types/build/lint) and traced against the Base UI `Tabs`/`ScrollArea` + shadcn `Textarea` APIs, not at runtime.
