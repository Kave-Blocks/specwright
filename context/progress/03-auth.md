# 03 — auth

Spec: [`context/feature-specs/03-auth.md`](../feature-specs/03-auth.md)

- `03-auth.md` — `@clerk/ui` installed; `NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in` and `NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up` added to `.env.local` (previously missing, needed so `proxy.ts` and Clerk's own components can resolve the public auth paths from env rather than hardcoded strings). `proxy.ts` created at the project root (Next.js 16 renamed `middleware.ts` → `proxy.ts`) using `clerkMiddleware` + `createRouteMatcher` in protected-first mode: only `${NEXT_PUBLIC_CLERK_SIGN_IN_URL}(.*)` and `${NEXT_PUBLIC_CLERK_SIGN_UP_URL}(.*)` are public, everything else calls `auth.protect()`. `app/layout.tsx` wraps `<body>` with `ClerkProvider` using the `dark` theme from `@clerk/ui/themes`, with `appearance.variables` overridden to reference the app's existing CSS custom properties (`var(--accent-primary)`, `var(--bg-surface)`, `var(--text-primary)`, etc.) instead of hardcoded colors — `borderRadius` maps to `var(--radius-2xl)` (card-level radius) and `fontFamily` to `var(--font-geist-sans)`. `components/auth/auth-layout.tsx` is a shared server component implementing the two-panel spec: `lg:grid-cols-2` 50/50 grid with a left brand panel (hidden below `lg`) and a right panel centering the Clerk form. The left panel is an elevated `bg-surface` (distinct from the `bg-base` right side, with a `border-r`), laid out as a flex column with `justify-between`: a brand lockup at top (cyan `bg-brand` rounded-square logo mark with a `Ghost` lucide icon in `text-primary-foreground` + "Specwright"), a centered content block (a `text-4xl`/`xl:text-5xl` headline "Design systems at the speed of thought.", a tagline, and a three-item feature list where each row pairs a tokened icon in a `bg-elevated` rounded square — `Sparkles`/`Share2`/`FileText` in `text-brand` — with a title and one-line description), and a `text-copy-faint` copyright footer at the bottom. No gradients or bordered feature cards; fits the viewport (no scroll). `app/sign-in/[[...sign-in]]/page.tsx` and `app/sign-up/[[...sign-up]]/page.tsx` render `<SignIn />`/`<SignUp />` inside `AuthLayout`. `app/page.tsx` (`/`) is now an async Server Component that calls `auth()` and redirects to `/editor` when `isAuthenticated`, otherwise to `/sign-in` — `/editor` itself does not exist yet (it's built in `08-editor-workspace-shell.md`), so this redirect currently 404s for authenticated users until that unit lands; this is expected incremental state, not a defect. `components/editor/editor-navbar.tsx`'s right section now renders Clerk's built-in `<UserButton />` (unmodified/undecorated, per spec — no custom appearance beyond the global `ClerkProvider` theme). Verified with `npm run build`, and in a real browser via Playwright: `/`, `/editor` → 307 to `/sign-in` when signed out; `/sign-in`, `/sign-up` → 200; dark two-panel layout confirmed at 1440px and form-only layout confirmed at 400px; cross-links between sign-in/up resolve to local routes (confirming the env vars are wired correctly), not Clerk-hosted URLs. Follow-up UI pass (per screenshot direction): reworked the left panel from a bare wordmark/text list into the richer brand panel described above and set the page `<title>` to "Specwright". Confirmed via Playwright computed styles that the headline, Clerk card heading, and body all resolve to `Geist, "Geist Fallback"` — Geist was already applied correctly (the earlier "wrong font" impression was the unpolished old layout, not an actual font bug). Note: attempted `appearance.options`/`layout.socialButtonsVariant: "blockButton"` to stack the social buttons as in the screenshot, but neither key changed the rendering in `@clerk/nextjs` 7.5.14 (Clerk renders icon-style social buttons by default here); reverted rather than leave dead config, since the spec says not to heavily customize Clerk internals.
