# 16 — edge-behavior

Spec: [`context/feature-specs/16-edge-behavior.md`](../feature-specs/16-edge-behavior.md)

- `16-edge-behavior.md` — complete. Replaced React Flow's default edges with a custom canvas edge that is easier to follow/click and supports inline labels, plus four-sided connection handles on every node. **Connection handles** (`canvas-node.tsx`): the node wrapper is now a `group` and renders four `<Handle>`s — one per side (`top`/`right`/`bottom`/`left`), each `type="source"` with a **position-based `id`** so the four same-type handles stay unambiguous and edges route from the correct side; `ConnectionMode.Loose` (already set on `<ReactFlow>`) lets any handle connect to any other. Handles are styled as **small white dots with a dark border** via `HANDLE_DOT` (`!h-2.5 !w-2.5 !border-[1.5px] !border-[color:var(--bg-base)] !bg-white` — the `!` overrides win over React Flow's `.react-flow__handle` theme rules) and are **hidden at rest, fading in on node hover** (`opacity-0 group-hover:opacity-100`) — or staying visible while the node is `selected` (computed with `cn(...)` off the `selected` prop, because React Flow's `.selected` class lives on an ancestor `.react-flow__node`, so a `group-[.selected]` variant would not match). **Default edge style + custom type** (`types/canvas.ts`): added `CANVAS_EDGE_COLOR = "#f8fafc"` (the ui-context Edge Style color — a raw string at the React Flow boundary, same accepted exception as the Background/MiniMap colors, since RF edge/marker props can't take Tailwind tokens) and `DEFAULT_EDGE_OPTIONS` (`type: CANVAS_EDGE_TYPE`, `markerEnd: { type: MarkerType.ArrowClosed, 18×18, color }`, and a light `stroke` `strokeWidth: 1.5` `strokeLinecap: "round"`). `CanvasEdgeData = { label?: string }` and `CanvasEdge` now carries it (was `Record<string, unknown>`). **`onConnect` rework** (`canvas.tsx`): Liveblocks' own `onConnect` builds edges with `addEdge(connection, [])`, which does **not** apply React Flow's `defaultEdgeOptions` (verified in `@liveblocks/react-flow`'s `flow.js`) — so the RF `defaultEdgeOptions` prop alone would never reach a new connection. Instead a custom `handleConnect` calls `createCanvasEdge(connection)` (`lib/canvas-edge.ts` — merges `DEFAULT_EDGE_OPTIONS`, a monotonic `edge-<ts>-<n>` id, the connection's source/target/handles, and `data: { label: "" }`) and adds it via `onEdgesChange([{ type: "add", item }])`, whose `applyEdgeChanges` `"add"` case writes it to Storage — so new connections render through the custom edge type **and** sync. `defaultEdgeOptions={DEFAULT_EDGE_OPTIONS}` is still passed to `<ReactFlow>` as the documented default and the edge is now registered via `edgeTypes={{ [CANVAS_EDGE_TYPE]: CanvasEdgeRenderer }}`. **Custom edge renderer** `components/editor/canvas/canvas-edge.tsx`: routes with clean right-angle steps via `getSmoothStepPath({ ..., borderRadius: 8 })`, draws the visible line with `<BaseEdge interactionWidth={0}>` (I supply my own hit area) at `strokeWidth 1.5` `strokeLinecap round`, and dims/brightens by `strokeOpacity` (`0.5` at rest → `1` when `active = selected || hovered`, 150ms transition). A **wide transparent interaction path** (`strokeWidth 22`, `stroke="transparent"`, `style={{ pointerEvents: "stroke" }}`) makes the edge easy to hover/click **without thickening the visible line** and carries the `onMouseEnter`/`onMouseLeave` (hover state) and `onDoubleClick` (open editor) handlers — so **hover, selection, and label editing are all handled inside the custom edge renderer**. **Inline labels** use `EdgeLabelRenderer` positioned at the `labelX`/`labelY` returned by `getSmoothStepPath` (`transform: translate(-50%,-50%) translate(labelX,labelY)`) — **midpoint is never computed manually**, per spec. Double-clicking the edge (or the label) opens an inline editor: an **auto-growing input** built with the CSS-grid mirror-span trick (an `aria-hidden` `whitespace-pre` span and the `<input size={1}>` share grid cell `1/1`, so the container width tracks the text with no JS measurement); it **saves on blur, Enter, or Escape** (all close the editor; the value is already committed live on each keystroke through `updateEdgeLabel`, mirroring the node-label flow). Saved labels show as **small pill badges** (`rounded-full border-surface-border bg-surface/95 text-copy-secondary`, `max-w-55 truncate`); an **active edge with no label shows a faint dashed-border hint** ("Add label", `text-copy-faint`). The label wrapper carries `nodrag nopan` + `pointerEvents: "all"` + `stopPropagation` on click/pointerdown so **label clicks and typing never drag a node or pan the canvas**, and the double-click handler `stopPropagation`s to swallow RF's zoom-on-double-click. **Collaborative wiring**: `canvas-context.ts` was generalized from `CanvasNodeActions`/`useCanvasNodeActions` → `CanvasActions`/`useCanvasActions`/`CanvasActionsProvider` (only two consumers) and gained `updateEdgeLabel(id, label)`; `CanvasFlow` implements it exactly like `updateNodeLabel` — finds the edge in the synced `edges` and emits a `"replace"` change with the patched `data.label` (`applyEdgeChanges` `"replace"` → `reconcile` into Storage). `EDGE_BASE_CONFIG` leaves `data` to the user just like `NODE_BASE_CONFIG`, so edge-label sync works identically to the already-working node-label sync. **Scope honored:** node creation, the shape panel, and the node renderer (beyond adding the styled handles + `group`) were left untouched. Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean). **Not exercised live in-browser**: a real `LIVEBLOCKS_SECRET_KEY` is now provisioned, but the editor is behind the Clerk auth wall and this session has no sign-in credentials — the handle/edge/label rendering and the connect→add / label→replace Storage paths are verified structurally (types/build) and traced against the `@xyflow/react` + `@liveblocks/react-flow` source, same constraint as `10`–`15`.
