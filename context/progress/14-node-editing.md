# 14 — node-editing

Spec: [`context/feature-specs/14-node-editing.md`](../feature-specs/14-node-editing.md)

- `14-node-editing.md` — complete. Added node **resizing** and **inline label editing**, both routed through the existing Liveblocks-backed node-change flow. **Resizing** `components/editor/canvas/canvas-node.tsx`: the renderer now mounts `<NodeResizer>` (from `@xyflow/react`) as the first child of the `relative h-full w-full` wrapper, `isVisible={selected}` so handles only appear on the selected node, `minWidth={80}`/`minHeight={48}` to floor the size, and styled subtle/dark-consistent via `color="var(--accent-primary)"` + `handleStyle={{ width: 8, height: 8, borderRadius: 2 }}`. `NodeResizer` dispatches `dimensions` (with `setAttributes`) + `position` changes through React Flow's standard change pipeline → the same `onNodesChange` from `useLiveblocksFlow`, and Liveblocks' `applyNodeChanges` writes `width`/`height`/`position` to Storage (verified in `@liveblocks/react-flow`'s `flow.js`: the `dimensions` case sets `node.set("width"/"height")` and pauses/resumes history around `resizing`), so resizes sync. **Inline label editing** is layered over the existing centered label: the wrapper gained an `onDoubleClick` (`stopPropagation` to swallow React Flow's zoom-on-double-click) that opens edit mode; the label region (`absolute inset-0 flex items-center justify-center px-3`) swaps its `<span>` for a `<textarea>` when editing. The textarea is transparent/borderless/centered (`nodrag nopan w-full resize-none border-0 bg-transparent text-center text-sm text-copy-primary outline-none`), `rows={1}` and auto-grown to `scrollHeight` in a `useLayoutEffect` so the node body never shifts layout; a second `useLayoutEffect` focuses it and drops the caret at the end when editing opens. Typing calls `updateNodeLabel(id, value)` on every `onChange` (live-updating the shared label) alongside a local `draft` for smooth caret behavior; `onBlur` and `Escape` (`onKeyDown`) both close editing; `nodrag`/`nopan` classes + `onPointerDown` `stopPropagation` keep text selection from dragging the node or panning the canvas. **Placeholder** ("Add label", `text-copy-faint`) renders in the same centered slot both at rest (empty label) and as the textarea's `placeholder`. **Collaborative wiring** — a custom node can't reach `onNodesChange`, so a new `components/editor/canvas/canvas-context.ts` exposes `CanvasNodeActions.updateNodeLabel` via `CanvasNodeActionsProvider`/`useCanvasNodeActions`; `CanvasFlow` (`canvas.tsx`) builds `updateNodeLabel` from the synced `nodes` + `onNodesChange` — it finds the node and emits a `"replace"` change carrying the full node with the patched `data.label` (Liveblocks' `applyNodeChanges` `replace` case `reconcile`s it into Storage), then wraps `<ReactFlow>` in the provider so custom nodes rendered inside the flow can consume it. Chose the `"replace"` change over React Flow's `useReactFlow().updateNodeData`, which only mutates the local store (`setNodes`, no `onNodesChange`) and would be overwritten by Liveblocks' controlled props on the next render — i.e. it would not persist/sync. **Scope honored:** shape rendering (`node-shape.tsx`), the shape panel, the drag preview, and the drop→`createCanvasNode` path were all left untouched. Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean). **Not exercised live in-browser** for the same reason as `10`–`13`: no real `LIVEBLOCKS_SECRET_KEY` is provisioned, so the room can't authenticate; the resize→dimensions-change and label→replace-change persistence paths are verified structurally (types/build) and against the Liveblocks change-handling source, not at runtime.
