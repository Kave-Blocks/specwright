# 18 — starter-templates

Spec: [`context/feature-specs/18-starter-templates.md`](../feature-specs/18-starter-templates.md)

- `18-starter-templates.md` — complete. Added a starter template library so users can replace the canvas with a prebuilt diagram. **Template data** `components/editor/starter-templates.ts` — a `CanvasTemplate` interface (`id`/`name`/`description`/`nodes`/`edges`) and `CANVAS_TEMPLATES` array with three templates (`microservices`, `cicd-pipeline`, `event-driven`), each 7 nodes / 6 edges. Built entirely from the **shared canvas types** (`CanvasNode`/`CanvasEdge`/`CanvasNodeShape`) and the **existing palette** — a named `PALETTE` map over `NODE_COLORS` (so template data reads `color: "blue"` instead of an index) and a `SHAPE_SIZES` map over `NODE_SHAPES` (so each node gets its shape's default footprint). Two small builder helpers keep the data readable: `node({id,label,shape,color,x,y})` → a full `CanvasNode` (`type: CANVAS_NODE_TYPE`, `style: {width,height}`, `data` with the paired fill/text colors), and `edge({source,target,label?,from?,to?})` → a full `CanvasEdge` that spreads `DEFAULT_EDGE_OPTIONS` (so template edges render **identically** to user-drawn ones — arrowhead + light stroke + custom edge type), ids as `${source}--${target}`, handles defaulting to `right`→`left` (matching the node's position-based handle ids `top/right/bottom/left`) and overridable per edge (the CI/CD `approve→rollback` edge routes `bottom`→`top`). `cloneTemplateGraph(template)` returns fresh `nodes`/`edges` (new `position`/`style`/`data` objects) so importing never mutates the exported constants and re-importing always restores the original layout. **Lightweight preview** `components/editor/starter-template-preview.tsx` — a static SVG with **no React Flow instance**: computes the graph's bounding box from node positions+sizes (`nodeBox`), pads it (40 flow units) into the `viewBox`, and uses `preserveAspectRatio="xMidYMid meet"` to fit the whole graph into a fixed `h-32 w-full` viewport. Edges draw as `<line>`s between node centers (rendered first so nodes sit on top); nodes draw per shape (`rect`/`pill`=stadium `rect`/`circle`=`ellipse`/`diamond`+`hexagon`=`polygon`/`cylinder`=body `path`+rim `ellipse`, mirroring `node-shape.tsx`), filled with the node's `color` and outlined in its paired `textColor`, all `vectorEffect="non-scaling-stroke"` so strokes stay crisp under the fit-scale. Edge stroke is set via `style={{ stroke: "var(--border-subtle)" }}` (CSS vars resolve in `style`, unlike bare presentation attributes). **Import modal** `components/editor/starter-templates-modal.tsx` — a Base UI `Dialog` (`sm:max-w-3xl`) with a scrollable (`ScrollArea max-h-[60vh]`) `sm:grid-cols-2` grid of cards; each card = preview + name + `line-clamp-2` description + a full-width **"Use template"** button whose `handleImport` calls `onImport(template)` **then** closes the dialog. **Canvas wiring** (`canvas.tsx`): `CanvasFlow` consumes a new `useStarterTemplates()` context and renders `<StarterTemplatesModal>` as a sibling of `<ReactFlow>`/`CanvasControls`/`ShapePanel`, wired to an `importTemplate` handler. **Critical collaborative-state mechanic:** Liveblocks' `applyNodeChanges`/`applyEdgeChanges` treat a `"remove"` change as a **no-op** (confirmed by reading `@liveblocks/react-flow`'s `flow.js` — `case "remove": break;`); deletion only happens through **`onDelete`**, which `.delete()`s ids from the `nodes`/`edges` LiveMaps. So `importTemplate` **clears** the current graph with `onDelete({ nodes, edges })`, then **adds** the template's cloned nodes/edges via `onNodesChange`/`onEdgesChange` `"add"` changes (reconciled into Storage) — the template **replaces** the canvas rather than layering on top, and every mutation stays in the shared collaborative state. `fitView({ duration: ZOOM_DURATION })` (duration imported from `useKeyboardShortcuts`, shared with the control bar) runs inside a **double `requestAnimationFrame`** so React Flow's internal store reflects the newly-added nodes before the fit is measured. **Cross-room-boundary bridge** `components/editor/starter-templates-context.ts` — `StarterTemplatesProvider`/`useStarterTemplates` expose `{ isOpen, setOpen }`; the navbar (outside the Liveblocks room) opens the modal, while the modal + import action live inside the canvas (inside the room, where the synced node/edge state is available). `EditorWorkspace` owns the `isTemplatesOpen` state, wraps its subtree in the provider, and passes `onOpenTemplates` to `WorkspaceNavbar`, which renders a ghost `LayoutTemplate` **"Templates"** button in the right cluster (before Share). **Scope honored:** no template saving, no custom user templates, no server persistence, and node/edge **rendering behavior is unchanged** (templates reuse `DEFAULT_EDGE_OPTIONS` and the existing node/edge schema). Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean), plus two headless checks (tsx): (1) every template edge references a real node id, ids are unique, node/edge `type`s + colors + `DEFAULT_EDGE_OPTIONS` are present, the preview `viewBox` math is finite/positive, and `cloneTemplateGraph` returns reference-independent objects; (2) a `react-dom/server` render of `StarterTemplatePreview` for all three templates produced valid SVG with the expected line/shape counts and **no `NaN`/`undefined`**. **Not exercised live in-browser** for the same reason as `10`–`17`: the editor is behind the Clerk auth wall and this session has no sign-in credentials, so the import→`onDelete`/`add` Storage round-trip and post-import `fitView` are verified structurally (types/build/lint + the two headless checks) and traced against the `@liveblocks/react-flow` + `@xyflow/react` source, not at runtime.
