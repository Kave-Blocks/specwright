# 13 — node-shape

Spec: [`context/feature-specs/13-node-shape.md`](../feature-specs/13-node-shape.md)

- `13-node-shape.md` — complete. Replaced the placeholder single-rectangle node renderer with per-shape rendering and added a shape drag preview. **Shared shape component** `components/editor/canvas/node-shape.tsx` (`NodeShape({ shape, color, selected })`) draws the visual body of a node, filling its parent (which owns the size): `rectangle`/`pill`/`circle` render as an `absolute inset-0` CSS `<div>` (border + `backgroundColor: color`) — `rectangle` → `rounded-xl`, `pill`/`circle` → `rounded-full` (pill's 160×64 reads as a pill, circle's 110×110 as a circle); `diamond`/`hexagon`/`cylinder` render as an `absolute inset-0 h-full w-full` `<svg viewBox="0 0 100 100" preserveAspectRatio="none">` so the shape **stretches to scale with node size**, with `vectorEffect="non-scaling-stroke"` keeping the 2px stroke uniform despite the non-uniform scale (diamond = `<polygon>` `50,1 99,50 50,99 1,50`; hexagon = `<polygon>` `25,1 75,1 99,50 75,99 25,99 1,50`; cylinder = a body `<path>` `M1,12 L1,88 A49,11 0 0 1 99,88 L99,12` with a full top `<ellipse>` for the rim, points inset by 1 so the stroke isn't clipped). **Borders subtle at rest / brighter when selected**: CSS shapes toggle `border-surface-border`→`border-brand`; SVG shapes toggle `stroke` between `var(--border-default)` and `var(--accent-primary)` (the same two tokens, referenced as CSS vars because SVG attrs can't take Tailwind classes). **Node renderer** `components/editor/canvas/canvas-node.tsx` is now a `relative h-full w-full` wrapper holding `<NodeShape>` + the four `<Handle>`s (unchanged) + a centered `absolute inset-0` label span (`text-copy-primary`, `wrap-break-word` — the Tailwind v4 canonical for the old `break-words`); it now reads `selected` from `NodeProps` and forwards it to `NodeShape`. **Drag preview** `components/editor/canvas/shape-panel.tsx`: `handleDragStart` still writes the `SHAPE_DRAG_MIME` payload, and now also calls `event.dataTransfer.setDragImage(preview, size.width/2, size.height/2)` — a ghost of the dragged shape centered under the cursor. The previews are six off-screen `<div>`s (one per shape, sized to `defaultSize`, each rendering `<NodeShape color={DEFAULT_NODE_COLOR}>`) kept **rendered but pushed off-screen** (`absolute top-0 left-[-9999px]`, `pointer-events-none`, `aria-hidden`) since `setDragImage` can't snapshot a `display:none` element; the browser keeps the image attached to the cursor and clears it on drop/cancel, so no explicit hide logic is needed. **Scope honored:** shape-panel layout, the drop→`createCanvasNode` path, resize, and label editing were all left untouched; the only drag change is the ghost image. Verified with `npm run build` (TypeScript clean, no type errors) and `npm run lint` (clean). **Not exercised live in-browser** for the same reason as `10`–`12`: no real `LIVEBLOCKS_SECRET_KEY` is provisioned, so the room can't authenticate; the shape rendering and drag-image wiring are verified structurally via the type/build checks.

### Follow-up — 2026-07-10

- **Shape drag-and-drop fixes** (two reported issues: no shape visible while dragging, and the shape jumping away from the cursor on drop): (1) *Invisible drag ghost* — `shape-panel.tsx` handed `setDragImage` an element parked at `left:-9999px`; browsers can only rasterize a drag image from an element painted **within the viewport**, so an off-screen element yields a blank ghost. Fixed by cloning the matching off-screen preview into `document.body` on `dragStart`, positioning the clone `fixed` at the cursor (`clientX/Y − size/2`, so it coincides with where the drag image renders → no flash), calling `setDragImage` with the centered `(w/2, h/2)` hotspot, then removing the clone on the next `requestAnimationFrame` (the drag-image snapshot is taken right after the handler returns, before rAF fires, so the element is still present). The off-screen previews remain as clone templates. (2) *Drop offset* — `canvas.tsx` `onDrop` placed the node's **top-left** at the cursor (`createCanvasNode(position)` where `position` = `screenToFlowPosition(cursor)`), but the ghost is centered on the cursor, so the node landed down-and-right of the ghost. Fixed by offsetting the flow position by half the node size (`point.x − size.width/2`, `point.y − size.height/2`) so the node's **center** lands at the cursor, matching the centered ghost. The theme CSS vars the cloned ghost relies on (`--bg-base`, `--border-default`, `--accent-primary`) are defined on `:root` in `globals.css`, so the body-level clone renders on-theme. Verified with `tsc --noEmit` and `eslint` (both clean); the native drag-image visibility is best confirmed by a manual drag in-browser (a native OS/compositor artifact, not observable in the DOM), while the centered-drop math is deterministic.
