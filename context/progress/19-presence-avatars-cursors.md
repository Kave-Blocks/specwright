# 19 — presence-avatars-cursors

Spec: [`context/feature-specs/19-presence-avatars-cursors.md`](../feature-specs/19-presence-avatars-cursors.md)

- `19-presence-avatars-cursors.md` — complete. Added active-participant presence to the canvas view: an avatar group + live cursors, plus the spec's Presence-field rename. **Presence type (item 5)** `liveblocks.config.ts`: renamed the `isThinking` field to **`thinking`** so Presence is exactly `{ cursor: { x: number; y: number } | null; thinking: boolean }` per spec; the only other reference — `canvas-room.tsx`'s `initialPresence` — was updated to `{ cursor: null, thinking: false }` (both are the sole `isThinking` usages, confirmed by grep, so the rename is complete). **Collaborator avatar** `components/editor/canvas/collaborator-avatar.tsx` (`CollaboratorAvatar`) — a **display-only** avatar (`size-7 rounded-full ring-2 ring-surface`; the subtle surface-colored ring keeps it readable on the near-black canvas and cleanly separates overlapped avatars): renders the profile photo when `avatar` is a non-empty URL (plain `<img>` with a scoped `no-img-element` eslint-disable — avatar hosts aren't configured for `next/image`, same exception as `share-dialog`), otherwise an **initials** fallback (first letters of the first two words, "?" fallback) in a circle tinted with the participant's presence `color` and dark `var(--bg-base)` text. No click/hover/focus — only a native `title` tooltip, honoring "not interactive." **Presence avatar group** `components/editor/canvas/presence-avatars.tsx` (`PresenceAvatars`) — pinned `absolute top-4 right-4 z-10` **inside the canvas view** (rendered only in `CanvasFlow`, never in either navbar, so it appears in the editor room canvas only and is visually separate from the fixed navbar's Templates/Share/AI cluster which sits above it). Current user id comes from the **Clerk session** (`useUser().user.id`); collaborators come from Liveblocks `useOthers()`, filtered to **exclude any entry whose `id` matches the current Clerk user id** (so the user is never shown as their own collaborator, even across their own extra tabs) and **deduped by user id** (one avatar per collaborator regardless of connection count). Up to **5** avatars render in an overlapping `-space-x-2` stack; a **`+N` overflow chip** (`bg-elevated`, same `size-7` + ring) appears when there are more than five. A **divider** (`h-6 w-px bg-surface-border`) renders **only when ≥1 collaborator exists**; with none, only the UserButton shows. The current user is rendered **separately** via the existing Clerk `<UserButton appearance={{ elements: { avatarBox: "size-7" } }}>` — sized to match the collaborator avatars, no second avatar drawn for them from presence, and Clerk's profile/logout behavior left untouched. **Live cursors (item 4)** — `components/editor/canvas/cursor.tsx` (`Cursor`) draws one remote cursor: a small colored pointer (the classic Liveblocks arrow path, `fill` = the participant's presence `color`) with an **attached name badge** (`backgroundColor: color`, dark `var(--bg-base)` text), positioned via `translate` with a short `transition-transform` to smooth Liveblocks' throttled presence updates. `components/editor/canvas/live-cursors.tsx` (`LiveCursors`) is a `pointer-events-none absolute inset-0 z-10` overlay rendered **as a child of `<ReactFlow>`** (so it fills the `.react-flow` pane, whose top-left is the origin `screenToFlowPosition` measures against). It reads the viewport transform `[translateX, translateY, zoom]` via `useStore` and maps each other's **flow-coordinate** cursor back to pane pixels (`x*zoom+tx`, `y*zoom+ty`) — mirroring how the pane itself is transformed — so cursors stay **anchored to the canvas content** as any viewer pans/zooms. It draws **others only** (`useOthers` excludes self, plus a guard on the Clerk id for the user's own extra tabs) and skips null cursors. **Canvas wiring** `canvas.tsx`: added `useUpdateMyPresence()`; `handleMouseMove` converts `event.clientX/Y` → flow coords via the existing `screenToFlowPosition` and broadcasts `{ cursor: { x, y } }`; `handleMouseLeave` clears `cursor` to `null`. Both are attached to `<ReactFlow onMouseMove/onMouseLeave>` — valid because `ReactFlowProps extends Omit<HTMLAttributes<HTMLDivElement>, "onError">`, so raw DOM handlers land on the pane wrapper and fire continuously (including over nodes), matching the spec's "onMouseMove" / "clear on mouse leave" wording. `<LiveCursors />` is added inside `<ReactFlow>` (after `<Background>`) and `<PresenceAvatars />` as a sibling of `<CanvasControls>`/`<ShapePanel>` in the `relative h-full w-full` wrapper. Cursors are broadcast in flow coordinates (anchored to content), not screen coordinates. **Scope honored:** the editor home navbar (`editor-navbar.tsx`) and the workspace navbar are untouched (no avatars added to shared navbar; no Save/Import/Share/AI actions removed); Clerk user/profile/logout behavior is preserved; collaborator avatars are non-interactive; node/edge behavior is unchanged. Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean). **Not exercised live in-browser** for the same reason as `10`–`18`: the editor is behind the Clerk auth wall and this session has no sign-in credentials, so the presence broadcast (`onMouseMove` → `updateMyPresence`), the `useOthers`-driven avatar filtering/dedup, and the flow↔pane cursor coordinate mapping are verified structurally (types/build/lint) and traced against the `@liveblocks/react` presence hooks + `@xyflow/react` `useStore`/`screenToFlowPosition` APIs, not at runtime.
