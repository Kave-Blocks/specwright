# Liveblocks provisioning QA follow-up

_2026-07-13 — not spec-driven._

- **Liveblocks provisioning QA follow-up — one real bug found by code review and fixed, but *not* the way the reviewer prescribed; a second, worse instance of the same bug was found three lines away.** CodeRabbit flagged `ensureFeed` (`lib/liveblocks.ts`) for treating **every** lookup failure as "feed missing" and **every** creation failure as a lost race: a bad key, a 429, a network blip, or a 5xx all resolved as **success**, so callers proceeded as though the feed existed while the root cause was discarded — and with both `catch` blocks bare, **no log line was emitted anywhere**. The diagnosis was correct and reproduced: with an invalid secret the old helper resolved cleanly. **The prescription — "propagate other failures" — was only half right, and applying it literally would have introduced a worse bug.** `ensureAiStatusFeed` sits **unguarded inside `design-agent`'s main `try`** (`trigger/design-agent.ts`), so making the helper throw would let a Liveblocks hiccup **fail — and then retry — an otherwise-healthy design run**. The status feed is *progress UI, not the job*: `announce()` directly below it already swallows-and-logs publish failures, and the canvas write path (`mutateFlow`) does not touch the feed at all. Best-effort is the **deliberate, correct contract** here. So the semantics were split: the **helper** is now honest, the **callers** stay best-effort but **log**. **Fix (feeds)** `ensureFeed` suppresses only the two statuses that actually mean "already settled" — **`404` on lookup** (feed absent → create it) and **`409` on create** (a concurrent caller won the race) — via a small `liveblocksStatus()` helper reading `LiveblocksError.status` (confirmed a **runtime** export, not type-only, so `instanceof` is sound). Everything else propagates. `design-agent` wraps the call in a `logger.warn` guard so a feed outage is recorded and **the canvas is still designed**; `/api/liveblocks-auth` keeps its non-fatal `catch` but now `console.error`s the cause instead of discarding it. **The second bug — `ensureRoom`, in the same route, had the identical swallow, and unlike the cosmetic feeds the room is load-bearing:** it was minting session tokens for rooms it had **never confirmed existed**, pushing the failure into the client with no server-side trace. It turned out the SDK ships **`getOrCreateRoom`** — literally `createRoom` with `?idempotent` (verified in the installed `dist/index.js`), a **single atomic call** that returns the room whether or not it existed. So the whole get-then-create dance **collapsed to one line** with no race to lose and no error to suppress; a genuine failure now fails the request. Feeds have **no such primitive** (no `getOrCreateFeed`/`upsertFeed`/`idempotent` flag), which is precisely why they still need the 404/409 handling. **The status codes were verified, not assumed — this was load-bearing.** The SDK's own types document `409` **only for threads**, never for feeds or rooms; had the codes been wrong, the new `ensureRoom` would **500 on a benign race**, worse than the bug being fixed. A probe against the **live Liveblocks API** (throwaway room, deleted afterwards) confirmed all four behaviors: `getFeed` on a missing feed → **404**; duplicate `createFeed` → **409**; `getOrCreateRoom` called twice → **no throw**; and three **concurrent** `ensureFeed` calls → all fulfilled. A fifth check proved the actual regression is gone: `ensureFeed` with an invalid key now **throws (403)** where it previously **resolved successfully** — note the real status is `403`, not `401`, which the fix handles correctly only because it propagates *everything* that isn't 404 rather than enumerating expected failures. **Verified:** `tsc --noEmit` and `eslint` clean on all three changed files, plus the live five-check probe above. **Not exercised:** the authenticated browser path (room entry → feed subscribe) — the editor is behind the Clerk auth wall, the same constraint as `10`–`29`; the provisioning logic it depends on is the code the live probe drove end to end.
