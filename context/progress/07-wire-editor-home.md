# 07 — wire-editor-home

Spec: [`context/feature-specs/07-wire-editor-home.md`](../feature-specs/07-wire-editor-home.md)

- `07-wire-editor-home.md` — wired the editor home to the real API and removed the mock data path. `app/editor/page.tsx` is now an **async Server Component** that calls the new `getEditorHomeProjects()` (`lib/projects-data.ts`) and passes `ownedProjects`/`sharedProjects` down to `EditorShell` — no client-side fetch for the initial load (invariant 4 / "server component" per spec). `lib/projects-data.ts` is the server-side data helper the spec calls for: it resolves owned projects `where ownerId = userId` and shared projects `where collaborators.some.email = <clerk email>` (email read via `currentUser()` — primary address, falling back to the first), both `orderBy createdAt desc`, and maps each Prisma row to the sidebar's `Project` UI shape via `toUiProject()` (sets `role` and `slug: project.id`, since the id *is* the room id). `hooks/use-project-actions.ts` was rewritten from a mock-list owner into a real API driver: it no longer holds a project array (lists come in as props from the server) and instead performs `fetch` mutations then re-reads server state. **Create:** `openCreate()` seeds a stable short suffix (`Math.random().toString(36).slice(2,8)`); `roomId` is derived reactively as `${slugify(name) || "project"}-${suffix}`; `submitCreate()` `POST`s `{ id: roomId, name }` and on success `router.push('/editor/'+roomId)`. **Rename:** `PATCH /api/projects/[id]` then `router.refresh()`. **Delete:** `DELETE /api/projects/[id]` then, if the deleted id equals the active room id (from `useParams<{roomId?}>()`), `router.push('/editor')`, else `router.refresh()`. All three guard against double-submit and `console.error` + keep the dialog open on a non-ok response. **API change (crosses into `06-project-apis.md`):** `POST /api/projects` now accepts an optional client-supplied `id` (validated by the new `normalizeId()` in `lib/projects-api.ts`) so the DB primary key stays aligned with the Liveblocks room id per the spec's "project ID and room ID should stay aligned"; a duplicate id is caught (`P2002`) and returned as `409` instead of a `500`. When `id` is absent the route still falls back to Prisma's `cuid()`. Wiring updates: `EditorShell` takes `ownedProjects`/`sharedProjects` props and forwards them into the hook; `project-dialogs.tsx` and `create-project-dialog.tsx` now pass/show `roomId` (the create dialog's preview line reads "Room ID: …") instead of the old bare slug; `mockProjects` was deleted from `lib/projects.ts` (only `slugify` + the `Project`/`ProjectRole` types remain). Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean). Note: `/editor/[roomId]` does not exist until `08-editor-workspace-shell.md`, so a freshly-created project navigates to a 404 for now — expected incremental state, same pattern as the `/` redirect in `03`.
