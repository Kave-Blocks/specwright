# 05 — prisma

Spec: [`context/feature-specs/05-prisma.md`](../feature-specs/05-prisma.md)

- `05-prisma.md` — data layer. `prisma/models/project.prisma` holds `ProjectStatus` (`DRAFT`/`ARCHIVED`), `Project` (`id` cuid PK, `ownerId` Clerk user, `name`, optional `description`, `status` default `DRAFT`, optional `canvasJsonPath`, `createdAt`/`updatedAt`, `@@index([ownerId])` + `@@index([createdAt])`) and `ProjectCollaborator` (`id` cuid PK, `projectId` + `project` relation with `onDelete: Cascade`, `email`, `createdAt`, `@@unique([projectId, email])`, `@@index([email])` + `@@index([projectId, createdAt])`). Multi-file schema enabled by pointing `prisma.config.ts` `schema` at the `prisma` directory (was `prisma/schema.prisma`); `prisma/schema.prisma` keeps only the `prisma-client` generator (output `app/generated/prisma`, already gitignored) + `postgresql` datasource. `lib/prisma.ts` is a `global`-cached singleton that branches on `DATABASE_URL`: `prisma+postgres://` → `new PrismaClient({ accelerateUrl })`, otherwise `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`. Migration `prisma/migrations/0_init/migration.sql` generated + applied. `prisma.config.ts` now loads `.env.local` first (then `.env`) via `dotenv` `config({ path: [...] })` — Next.js reads `.env.local` at runtime, so without this the CLI (which used bare `import "dotenv/config"` → `.env` only) would target a different DB than the app. Verified with `tsc --noEmit`, lint, `npm run build`, and runtime CRUD tests (create with nested collaborator, `DRAFT` default, cascade delete) through **both** branches: the direct `@prisma/adapter-pg` branch against a direct TCP port, and the **Accelerate branch** against a real Prisma Postgres cloud DB (`accelerate.prisma-data.net`).

### Resolved open question — database provisioning

- `DATABASE_URL` now points at a real Prisma Postgres cloud DB (`prisma+postgres://accelerate.prisma-data.net/...` in `.env.local`); the `0_init` migration is applied there and the Accelerate branch is verified end-to-end. (Earlier friction, resolved: the local `prisma dev` emulator — Postgres-wire over SQLite — rejected `migrate dev` on the shadow-DB step with `P1017` and refused HTTP/Accelerate queries for client 7.8.0. The migration was authored via `prisma migrate diff --from-empty --to-schema prisma --script` and applied with `prisma migrate deploy`, which is the flow that also works against the cloud DB.)
