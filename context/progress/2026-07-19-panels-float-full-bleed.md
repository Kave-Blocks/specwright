# Panels float over a full-bleed canvas

_2026-07-19 — not spec-driven._

- **Panels float over a full-bleed canvas (reverses the `08` docked-layout follow-up).** This settles the architectural decision deferred by the canvas visual QA pass above, in favor of `ui-context.md`'s documented floating-overlay design: the canvas now always spans the full workspace width and both side panels layer *on top* of it, so toggling a panel no longer resizes the canvas. Previously `ProjectSidebar`/`AiSidebar` took a `docked` prop that, at `md+`, turned them into in-flow flex columns and hid them by animating a negative margin (`md:-mr-80`/`md:-ml-80`) — that margin animation is precisely what squeezed the `flex-1` canvas on every toggle (and, because React Flow's internal `ResizeObserver` fires throughout the 200ms transition while nothing calls `fitView`, content visibly shifted/cropped). The `docked` prop is **removed entirely** rather than defaulted off: it was only ever set by `EditorWorkspace`, and both panels already carried a complete `position: fixed` slide-over treatment (used by the `/editor` home shell) that was simply being overridden at `md+`. Dropping it lets that one treatment apply at every breakpoint, so the two components now have a single layout mode instead of two. **Canvas chrome insets:** the panels are `z-30` and the canvas's floating chrome is `z-10`, so a full-bleed canvas puts `canvas-controls.tsx` (bottom-left: zoom/fit/undo/redo) under the *default-open* project sidebar and `presence-avatars.tsx` (top-right) under the AI panel — both would have been unreachable. `EditorWorkspace` therefore sets `--canvas-inset-left`/`--canvas-inset-right` (`20rem` when the corresponding panel is open, else `0px`) as inline CSS vars on `<main>`; the two overlays consume them via `left-[calc(1rem+var(--canvas-inset-left,0px))]` / `right-[calc(1rem+var(--canvas-inset-right,0px))]` with a matching `duration-200` transition, so they slide clear of whichever panel is open. CSS vars rather than props because the chrome renders deep inside the Liveblocks room subtree and the panel state lives in the shell — this avoids threading it through `CanvasSurface`. The vars deliberately move **only the chrome**; the canvas surface itself stays full-bleed under the panels. The bottom-center tool panel and top-center AI status feed are left alone — neither is covered by a 20rem side panel at desktop widths. Verified with `tsc --noEmit` and `eslint` (both clean); **not** verified in a live browser (the Playwright MCP Chrome profile was locked by a stray instance — see the note above — and the editor is behind the Clerk auth wall).
