# Editor QA / bug-fix pass

_2026-07-10 — not spec-driven._

- **Editor QA / bug-fix pass** (`context/current-issues.md`) — reviewed 5 reported issues; fixed the 3 that existed, verified 2 did not. **(2) Delete nodes/edges** — new `hooks/use-canvas-delete-keys.ts` (`useCanvasDeleteKeys(onDelete)`, called in `CanvasFlow`): a `window` keydown listener for **Delete/Backspace** that bails on editable targets (input/textarea/select/contentEditable), reads the selected elements from React Flow's store via `useNodes`/`useEdges` filtered by `selected`, and removes them through the existing Liveblocks-backed `onDelete` so deletions **sync to all clients**. Also deletes edges attached to any deleted node (matching RF's own semantics) so no dangling edge is orphaned in Storage. RF's built-in keyboard deletion is disabled with `deleteKeyCode={null}` so this is the single deletion path (selection is read via a ref, so the listener binds once). **(5) Auto-zoom on first node drop** — root cause was the declarative `fitView` prop on `<ReactFlow>`: with an initially-empty canvas it defers its one-time fit until the first node exists, so dropping the first node fit-zoomed to that single node. Removed the `fitView` prop and instead fit explicitly only when the room **already has content at mount** (reconnect — added to the load effect's skip branch, double-`rAF`), preserving fit-on-open for populated canvases while a truly empty canvas now gets no auto-fit and the viewport stays put on first drop. (The empty-room-with-saved-content path already fit after loading.) **(6) Collaborator avatar image host** — added `img.clerk.com` to `images.remotePatterns` in `next.config.ts` (previously empty). Note: collaborator avatars render via a plain `<img>` (so there was no active `next/image` host error), but the allow-list is now in place as specified. **(3) Connection handles — did NOT exist:** verified all four handles in `canvas-node.tsx` are present (`top`/`right`/`bottom`/`left`), all `type="source"` with the correct `Position`, share one class, run under `ConnectionMode.Loose`, and no component/global CSS hides or disables the non-top handles — all four are connectable, no change made. **(7) UserButton in workspace navbar — did NOT exist:** `WorkspaceNavbar` has no `UserButton` (and never did); the editor-home `EditorNavbar` is a **separate** component that keeps its `UserButton`. The "shared navbar / conditional render" premise doesn't apply, so nothing to remove (the workspace's own current-user avatar lives in `PresenceAvatars` on the canvas — presence UI, not the navbar — and was left untouched). Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean).
