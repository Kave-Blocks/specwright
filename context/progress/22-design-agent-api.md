- `22-design-agent-api.md` — complete. First unit of the **AI generation backend**: wired the Trigger.dev design flow — triggering background jobs, tracking runs, and issuing run-scoped tokens. **No AI logic, no node/edge/canvas changes** (explicit scope limits honored). **TaskRun model (item 2)** `prisma/models/task-run.prisma` (new file in the multi-file `prisma/models/` layout, matching `project.prisma`): `id` cuid PK + `runId String @unique` + `projectId String` + `userId String` + `createdAt`. The spec asks for both "`runId` unique" **and** "an index on `runId`" — `@unique` already emits a unique index (`TaskRun_runId_key`), which satisfies the index requirement; a separate `@@index([runId])` would be a redundant duplicate, so it was **not** added. Compound `@@index([userId, projectId])` per spec. `projectId` is a plain indexed string (no FK relation to `Project`) because the spec enumerates the fields exactly and a relation would require an `onDelete` decision + back-relation not in scope — still first-class relational metadata per `architecture-context.md`. **Migration** `prisma/migrations/20260710111436_add_task_run/migration.sql` — generated as an **incremental delta** (not a full re-diff) via `prisma migrate diff --from-schema <pre-22 datamodel copy> --to-schema prisma --script` (the `--from-schema-datamodel`/`--to-schema-datamodel` flags were **removed** in Prisma 7.8's CLI → use `--from-schema`/`--to-schema`; a temp copy of the schema folder minus `task-run.prisma` served as the "old" datamodel, avoiding a shadow DB). Applied to the real Prisma Postgres cloud DB with `prisma migrate deploy` (2 migrations found, `add_task_run` applied cleanly) and `prisma generate` regenerated the client (`app/generated/prisma/models/TaskRun.ts` now exists, `prisma.taskRun` accessor available). **Design task (item 4)** `trigger/design-agent.ts` — a **minimal** `task` (id `"design-agent"`), deliberately reusing the exact plain-`task` + `logger.info` pattern from the existing `trigger/example.ts` rather than introducing `schemaTask` (zod is **not** installed and the spec says reuse the existing setup). Accepts the spec payload `{ prompt, roomId }` (typed via an exported `DesignAgentPayload` interface), logs the input, and echoes `{ status: "received", roomId, prompt }`. **Trigger route (item 1)** `app/api/ai/design/route.ts` (`POST`) — accepts `{ prompt, roomId, projectId }`; because `projectId` arrives in the **body** (not a `[projectId]` path param), the `withProjectMember` wrapper (params-based) doesn't fit, so the route runs that wrapper's logic **inline**: `getClerkIdentity()` → 401, validate input (`normalizeName` for the free-text prompt — same helper already used for the free-text `description` field — and `normalizeId` for the two ids) → 400, `getAccessibleProject(projectId, identity)` → 404 (owner **or** collaborator may generate, mirroring the collaborative canvas). Then triggers via a **type-only import** (`import type { designAgent }` + `tasks.trigger<typeof designAgent>("design-agent", { prompt, roomId })` — never importing the task instance into the route bundle), records the run with `prisma.taskRun.create({ runId: handle.id, projectId, userId })`, and returns `{ runId: handle.id }` (201). Handler order: auth → input validation → access check → trigger → persist (access check necessarily follows body parse since the id is in the body). **Token route (item 3)** `app/api/ai/design/token/route.ts` (`POST`) — uses the `withAuth` wrapper (ownership is via `TaskRun.userId`, no path param): validates `runId` (`normalizeId`) → 400, looks up the `TaskRun` by `runId` (missing → 404, `taskRun.userId !== userId` → 403, mirroring the `verifyProjectOwnership` 404/403 masking), then mints a **run-scoped** read token `auth.createPublicToken({ scopes: { read: { runs: [runId] } } })` (from `@trigger.dev/sdk`; a scopeless token authorizes nothing) and returns `{ token }`. **ESLint config touch** `eslint.config.mjs` — added `.trigger/**` to `globalIgnores`: this is the first unit with Trigger.dev code, and its git-ignored build cache (`.trigger/tmp/build-*`) was newly surfaced to ESLint's flat config (which lints dot-dirs by default), producing 136 errors purely in that cache; ignoring it (matching `.gitignore`) is the root-cause fix and restores clean `npm run lint`. Verified: `tsc --noEmit` clean, `npm run lint` clean (exit 0), `npm run build` clean (both routes registered as dynamic function routes `ƒ /api/ai/design` + `ƒ /api/ai/design/token`), and a **live dev-server smoke test** — unauthenticated `POST` to both routes returned clean `401 {"error":"Unauthorized"}` (proving the routes compile/run and the auth guard fires before any DB/Trigger.dev work), with no compile errors in the dev log. **Not exercised authenticated end-to-end** (the real trigger→TaskRun→token round-trip): the routes sit behind the Clerk auth wall and this session has no sign-in credentials — same constraint as `10`–`21`; the trigger/persist/token paths are verified structurally (types/build/lint + the unauth smoke test) and traced against the pinned `@trigger.dev/sdk` skill docs (`tasks.trigger` handle `.id` = run id; `auth.createPublicToken` run-scope shape), not via a signed-in call to the live Trigger.dev project.
