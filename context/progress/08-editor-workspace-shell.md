# 08 — editor-workspace-shell

Spec: [`context/feature-specs/08-editor-workspace-shell.md`](../feature-specs/08-editor-workspace-shell.md)

- `08-editor-workspace-shell.md` — built the `/editor/[roomId]` workspace shell with server-side access checks; no canvas logic yet. **Access helpers** live in `lib/project-access.ts` (outside the page, per spec): `getClerkIdentity()` returns `{ userId, email }` (primary email via `currentUser()`, falling back to the first address; `null` when unauthenticated) and `getAccessibleProject(projectId, identity)` runs a single `findFirst` with `id` + `OR: [{ ownerId }, {collaborators.some.email}]` and a narrow `select: { id, name }` — returning `null` for **both** a missing project and one the identity can't access, so the two cases collapse to the same result and a non-member can't distinguish them. `app/editor/[roomId]/page.tsx` is an **async Server Component** (Next 16 `params` is a `Promise`): resolves `roomId`, then unauthenticated → `redirect("/sign-in")`, no accessible project → returns `<AccessDenied/>` (covers missing **and** unauthorized), otherwise fetches the sidebar's owned/shared lists via the existing `getEditorHomeProjects()` and renders `<EditorWorkspace/>` with the project name. `components/editor/access-denied.tsx` is a chrome-less server component: centered `flex-1` column, `Lock` icon in a `rounded-2xl bg-elevated` square, "Access denied" heading + short message, and a `Link` to `/editor` styled via `buttonVariants({ variant: "outline" })` (Base UI `Button` has no `asChild`, so the styled-Link pattern is used instead). **Workspace chrome** is a new client shell `components/editor/editor-workspace.tsx` (deliberately separate from the home `EditorShell`, whose `EditorNavbar` differs — see the pre-existing Architecture Decision): owns `isSidebarOpen` (default open) + `isAiSidebarOpen` (default closed), wraps the subtree in `ProjectActionsProvider` (so create/rename/delete + create-navigation still work inside a room) and renders `<ProjectDialogs/>`, the mobile scrim, both slide-over panels, and a central `bg-base` canvas placeholder in a `flex-1` `<main className="pt-14">`. `components/editor/workspace-navbar.tsx` is the room navbar (fixed h-14, `grid-cols-[1fr_auto_1fr]`): left = project-sidebar toggle (`PanelLeftOpen/Close`, kept so the overlay stays re-openable), center = truncating project name, right = a (visual-only, no behavior yet) `Share` outline button + a `Sparkles` AI-sidebar toggle that reflects open state via `aria-pressed` and an active `bg-elevated text-ai-text` class. `components/editor/ai-sidebar.tsx` mirrors the left sidebar's floating-overlay treatment on `right-3` (same navbar-height-derived top/height tokens, `translate-x` slide) with an "AI Assistant" header and a "coming soon" placeholder body. **Current-room highlight:** `useProjectActions` now also returns `activeRoomId` (already computed from `useParams<{roomId?}>()`); `ProjectSidebar` passes `isActive={project.id === activeRoomId}` to `ProjectItem`, which renders the active row with `bg-accent-dim` + `text-brand` and `aria-current="page"` (on the home route `roomId` is undefined → no highlight, unchanged). Verified with `tsc --noEmit`, `npm run lint`, and `npm run build` (all clean; `/editor/[roomId]` registered as a dynamic route). Note: real canvas, Liveblocks, AI chat, and sharing behavior are explicitly out of scope for this unit. **Follow-up fix:** the sidebar project row never navigated (only rename/delete were wired back in `07`), so clicking a project did nothing despite `04`'s "open an existing one / choose a project from the sidebar" copy. `ProjectItem`'s name/slug block is now a `next/link` `<Link href={/editor/${project.slug}}>` (slug === project.id === roomId) filling the `flex-1` area with a focus-visible ring; the rename/delete buttons remain siblings outside the link so their clicks don't navigate. **Follow-up (layout — docked panels):** the original shell placed both side panels as pure `position: fixed` floating overlays layered *over* a full-width canvas, so on desktop the open project sidebar covered the canvas's left edge and the canvas centered against the whole viewport rather than the space between the panels — the spec's "canvas fills the remaining space" was not really met. Reworked to a true docked layout: `ProjectSidebar`/`AiSidebar` gained a `docked` prop (default `false` keeps the `/editor` home's overlay behavior untouched) that, at `md+`, switches them from `fixed` to in-flow flex columns (`md:relative`, height auto to stretch the row) and collapses their footprint when closed via a negative margin (`md:-mr-80`/`md:-ml-80`) while retaining `w-80` so panel content never squishes mid-animation; below `md` they stay the original slide-over overlays with the scrim. `EditorWorkspace` now wraps `[sidebar · canvas · AI panel]` in a padded flex **row** (`p-3`, top padding derived from `--editor-navbar-height`) so the canvas (`flex-1`, now a bordered `rounded-2xl` card) genuinely fills the space between the two docked cards. Verified with `tsc --noEmit` (clean).
