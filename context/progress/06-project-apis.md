# 06 — project-apis

Spec: [`context/feature-specs/06-project-apis.md`](../feature-specs/06-project-apis.md)

- `06-project-apis.md` — backend-only project API. `app/api/projects/route.ts` (`GET` lists the authenticated user's own projects `where ownerId = userId`, `orderBy createdAt desc`; `POST` creates a project owned by the Clerk `userId`, defaulting a missing/blank name to `Untitled Project` and letting Prisma's `cuid()` supply the id — no sequential ids added, `201` on success). `app/api/projects/[projectId]/route.ts` (`PATCH` renames, `DELETE` removes — both owner-only). Shared boundary helpers live in `lib/projects-api.ts`: `readJsonBody()` (safe JSON parse → `{}` on malformed/non-object input), `normalizeName()` (trim → non-empty string or `null`, rejects non-strings), and `verifyProjectOwnership(projectId, userId)` returning a discriminated `{authorized:true} | {authorized:false, status:403|404}` (missing project → `404`, wrong owner → `403`, so a non-owner can't distinguish beyond the status code). Handler ordering per unit: auth (`401`) → ownership (`403`/`404`) → input validation (`400` on missing rename name) → mutation. **Middleware change (crosses into `03-auth.md`):** `proxy.ts` now excludes `/api/(.*)` from the protected-first `auth.protect()` via a new `isApiRoute` matcher, because `auth.protect()` answers unauthenticated requests with a `307` redirect to `/sign-in` — fine for page navigations but wrong for an API, which must return a JSON `401`. API routes now self-guard with `auth()` inside each handler (they already did), which is also the direction Clerk's own deprecation note recommends (per-route checks over centralized matching — see Open Questions). Page protection is unchanged: `/editor` etc. still `307` to sign-in when signed out. Verified: `npm run build`; unauthenticated `GET`/`POST`/`PATCH`/`DELETE` all return `401` (curl) while `/editor` still `307`s; and the full authenticated data path (create → cuid+`DRAFT` default, owner-scoped list with no cross-owner leak, `verifyProjectOwnership` owner/`403`/`404` decisions, rename, cascade-safe delete) exercised against the real Prisma Postgres DB via a throwaway `tsx` script.
