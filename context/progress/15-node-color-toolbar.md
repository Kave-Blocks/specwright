# 15 — node-color-toolbar

Spec: [`context/feature-specs/15-node-color-toolbar.md`](../feature-specs/15-node-color-toolbar.md)

- `15-node-color-toolbar.md` — complete. Added a floating per-node color toolbar so a selected node can change its **background + paired text color** on the canvas, all through the existing collaborative node-change flow (no server calls). **Palette source:** reused the existing `NODE_COLORS` (the 8 fill/text pairs from `ui-context.md`) already defined in `types/canvas.ts` — the pairs are canvas data, not theme tokens in `global.css`, so per the spec they stay in the canvas types. **Node data now carries the text color:** `CanvasNodeData` gained a `textColor` field (previously the label was hardcoded to `text-copy-primary`); `types/canvas.ts` adds `DEFAULT_NODE_TEXT_COLOR = NODE_COLORS[0].text` and `lib/canvas-node.ts`'s `createCanvasNode` now seeds `textColor: DEFAULT_NODE_TEXT_COLOR` alongside the default fill so every new node starts as a valid pair. **Toolbar** `components/editor/canvas/node-color-toolbar.tsx` (`NodeColorToolbar({ activeColor, onSelect })`) — a rounded pill (`bg-surface/95` + `border-surface-border` + `backdrop-blur`, matching the shape panel) positioned `absolute bottom-full left-1/2 mb-2 -translate-x-1/2` so it floats **slightly above the node without overlapping** it; one `h-5 w-5` round swatch per `NODE_COLORS` pair, each showing the `fill` as background with a small centered dot in the paired `text` color so the swatch communicates both colors. **Active** pair (`fill === data.color`) reads clearly selected via a bright 2-ring `boxShadow` (`0 0 0 2px var(--bg-surface), 0 0 0 3px <text>`) + a `text`-colored border; **hover** shows a tight, controlled glow (`0 0 6px 1px <text>` — small blur, low spread) tinted with the swatch's text color, plus a subtle `hover:scale-110`. **Interaction guards:** the container and every swatch carry `nodrag nopan` classes and `stopPropagation` on `onPointerDown`/`onClick`/`onDoubleClick`, so using the toolbar never drags the node or pans the canvas (and double-click on it doesn't open the label editor). **Wiring:** `canvas-context.ts`'s `CanvasNodeActions` gained `updateNodeColor(id, color, textColor)`; `canvas.tsx` implements it exactly like `updateNodeLabel` — finds the node in the synced `nodes` and emits a `"replace"` change carrying the full node with patched `data.color`/`data.textColor` (Liveblocks `applyNodeChanges` reconciles it into Storage, so the change **syncs and updates the node UI immediately** — controlled props re-render on the same tick). `canvas-node.tsx` renders `<NodeColorToolbar>` only when `selected`, wired to `updateNodeColor`, and the label span **and** inline textarea now take `style={{ color: data.textColor }}` (dropping the hardcoded `text-copy-primary`) so the node's text automatically reflects its paired text color; the "Add label" placeholder stays `text-copy-faint`. The node background already came from `data.color` via `NodeShape`, so a swatch selection updates fill + text together. **Scope honored:** drag/drop, node-selection logic, and the resize/label-edit flows were left untouched; no full color picker was added — only the predefined `NODE_COLORS` themes. Verified with `npm run build` (TypeScript clean) and `npm run lint` (clean). **Not exercised live in-browser** for the same reason as `10`–`14`: no real `LIVEBLOCKS_SECRET_KEY` is provisioned, so the room can't authenticate; the swatch→replace-change persistence path is verified structurally (types/build) and against the same Liveblocks change-handling used by the label edit in `14`.
